# AI Agent 工作流程

## 概述

本文件定义了 alphα 项目中 AI Agent 的标准工作流程。所有 Agent 都应遵循此流程执行任务。

## 工作流程

### 阶段 1: 任务接收

#### 1.1 任务分析
```
任务来源 → 任务描述 → 任务类型 → 优先级评估
```

**任务类型分类**:
- **新功能开发**: 需要创建新代码
- **Bug 修复**: 需要修复现有问题
- **代码重构**: 需要优化现有代码
- **文档编写**: 需要创建或更新文档
- **测试编写**: 需要创建测试用例
- **安全检查**: 需要进行安全审计
- **性能优化**: 需要优化性能

#### 1.2 资源准备
- 检查 .memory/daily/ 中的历史记录
- 查看相关设计文档 (.memory/design/)
- 查看相关需求规格 (.memory/specs/)
- 查看相关审查记录 (.memory/review/)

---

### 阶段 2: 技能选择

#### 2.1 技能匹配
根据任务类型选择合适的技能：

| 任务类型 | 主技能 | 辅助技能 |
|----------|--------|----------|
| 新功能开发 | yeahzero-thought-design | project-init, test-generator |
| Bug 修复 | code-review | test-generator |
| 代码重构 | code-review | performance-optimizer |
| 文档编写 | doc-generator | yeahzero-note-consolidate |
| 安全检查 | security-audit | code-review |
| 性能优化 | performance-optimizer | code-review |
| 版本发布 | deploy-automation | yeahzero-deliver-go |

#### 2.2 技能配置
```json
{
  "skill": "skill-name",
  "parameters": {
    "param1": "value1",
    "param2": "value2"
  },
  "options": {
    "auto_fix": false,
    "verbose": true
  }
}
```

---

### 阶段 3: 任务执行

#### 3.1 代码开发
```
需求分析 → 设计 → 编码 → 测试 → 审查
```

**编码规范**:
- 遵循项目命名规范
- 编写清晰的注释
- 保持代码简洁
- 遵循 SOLID 原则

#### 3.2 文档编写
```
需求分析 → 大纲 → 内容编写 → 审查 → 发布
```

**文档规范**:
- 使用 Markdown 格式
- 包含代码示例
- 保持结构清晰
- 定期更新

#### 3.3 测试编写
```
测试计划 → 测试用例 → 测试执行 → 测试报告
```

**测试规范**:
- 覆盖正常流程
- 覆盖边界情况
- 覆盖异常情况
- 保持测试独立

---

### 阶段 4: 记录过程

#### 4.1 每日工作日志
**文件位置**: `.memory/daily/YYYY-MM-DD.md`

**内容要求**:
```markdown
# 工作日志 - YYYY-MM-DD

## Agent: <agent-name>
## 任务: <task-description>

### 完成内容
- [x] 任务1
- [x] 任务2

### 遇到的问题
- 问题1: 描述
- 解决方案: 描述

### 使用的 Skill
- skill1: 用途说明

### 代码变更
- 文件1: 变更说明
- 文件2: 变更说明
```

#### 4.2 审查日志
**文件位置**: `.memory/review/YYYY-MM-DD-PR编号.md`

**内容要求**:
```markdown
# Code Review - YYYY-MM-DD - PR#<number>

## Agent: <agent-name>
## 任务: <task-description>

### 变更摘要
- 变更1
- 变更2

### 审查要点
- 代码质量: ✓/✗
- 安全性: ✓/✗
- 性能: ✓/✗
- 可维护性: ✓/✗

### 审查意见
- 意见1
- 意见2

### 结论
- [ ] 通过
- [ ] 需要修改
- [ ] 拒绝
```

#### 4.3 设计文档
**文件位置**: `.memory/design/<功能名>.md`

**内容要求**:
```markdown
# <功能名称> 设计文档

## 版本信息
- **版本**: 1.0.0
- **日期**: YYYY-MM-DD
- **作者**: 作者名

## 1. 背景与目标
### 1.1 背景
### 1.2 目标

## 2. 技术方案
### 2.1 架构设计
### 2.2 数据模型
### 2.3 接口设计

## 3. 实现细节
### 3.1 核心逻辑
### 3.2 边界情况

## 4. 测试策略
### 4.1 单元测试
### 4.2 集成测试

## 5. 部署计划
### 5.1 部署步骤
### 5.2 回滚方案
```

---

### 阶段 5: 提交审查

#### 5.1 代码审查
- 使用 code-review 技能
- 检查代码质量
- 检查安全性
- 检查性能
- 生成审查报告

#### 5.2 安全审查
- 使用 security-audit 技能
- 检查依赖漏洞
- 检查代码安全
- 检查配置安全
- 生成安全报告

#### 5.3 性能审查
- 使用 performance-optimizer 技能
- 分析性能瓶颈
- 检查内存使用
- 优化数据库查询
- 生成性能报告

---

### 阶段 6: 更新文档

#### 6.1 文档更新
- 更新 API 文档
- 更新用户手册
- 更新变更日志
- 更新 README

#### 6.2 知识积累
- 使用 yeahzero-extract-exp 提取经验
- 使用 yeahzero-note-consolidate 整合笔记
- 更新知识库

---

## 异常处理

### 任务阻塞
- 记录阻塞原因
- 寻求帮助
- 调整任务优先级

### 代码冲突
- 使用 Git 解决冲突
- 协商解决方案
- 必要时请求人工介入

### 质量问题
- 停止提交
- 修复问题
- 重新审查
