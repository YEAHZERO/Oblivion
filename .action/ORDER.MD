# 任务执行顺序说明

## 概述

本文件定义了 alphα 项目中 AI Agent 执行任务的标准顺序。所有 Agent 都应遵循此顺序执行任务。

## 执行顺序

### 阶段 1: 任务接收

```
任务来源 → 任务描述 → 任务类型 → 优先级评估
```

**检查项**:
- [ ] 理解任务需求
- [ ] 评估任务复杂度
- [ ] 确定任务优先级
- [ ] 分配任务资源

### 阶段 2: 资源准备

```
检查记忆 → 查看设计文档 → 查看需求规格 → 查看审查记录
```

**检查项**:
- [ ] 检查 .memory/daily/ 中的历史记录
- [ ] 查看相关设计文档 (.memory/design/)
- [ ] 查看相关需求规格 (.memory/specs/)
- [ ] 查看相关审查记录 (.memory/review/)

### 阶段 3: 技能选择

```
任务类型 → 技能匹配 → 技能配置
```

**技能选择表**:

| 任务类型 | 主技能 | 辅助技能 |
|----------|--------|----------|
| 新功能开发 | yeahzero-thought-design | project-init, test-generator |
| Bug 修复 | code-review | test-generator |
| 代码重构 | code-review | performance-optimizer |
| 文档编写 | doc-generator | yeahzero-note-consolidate |
| 安全检查 | security-audit | code-review |
| 性能优化 | performance-optimizer | code-review |
| 版本发布 | deploy-automation | yeahzero-deliver-go |

**检查项**:
- [ ] 选择合适的技能
- [ ] 配置技能参数
- [ ] 确认技能使用方式

### 阶段 4: 任务执行

```
需求分析 → 设计 → 编码 → 测试 → 审查
```

**执行规范**:
- 遵循编码规范
- 编写清晰的注释
- 保持代码简洁
- 遵循 SOLID 原则

**检查项**:
- [ ] 完成需求分析
- [ ] 完成设计
- [ ] 完成编码
- [ ] 完成测试
- [ ] 通过代码审查

### 阶段 5: 记录过程

```
创建工作日志 → 记录代码变更 → 记录遇到的问题
```

**记录位置**:
- 工作日志: `.memory/daily/YYYY-MM-DD.md`
- 审查日志: `.memory/review/YYYY-MM-DD-PR编号.md`
- 设计文档: `.memory/design/<功能名>.md`

**检查项**:
- [ ] 创建/更新工作日志
- [ ] 记录代码变更
- [ ] 记录遇到的问题
- [ ] 记录解决方案

### 阶段 6: 提交审查

```
代码审查 → 安全审查 → 性能审查
```

**审查内容**:
- 代码质量
- 安全性
- 性能
- 可维护性

**检查项**:
- [ ] 通过代码审查
- [ ] 通过安全审查
- [ ] 通过性能审查
- [ ] 解决所有审查意见

### 阶段 7: 更新文档

```
更新 API 文档 → 更新用户手册 → 更新变更日志
```

**文档位置**:
- API 文档: `docs/API使用及插件开发指南.md`
- 用户手册: `docs/项目使用说明文档.md`
- 变更日志: `.changelog/YYYY-MM-DD.md`

**检查项**:
- [ ] 更新 API 文档
- [ ] 更新用户手册
- [ ] 更新变更日志
- [ ] 更新 README

### 阶段 8: 任务完成

```
验证结果 → 总结经验 → 提交代码 → 关闭任务
```

**检查项**:
- [ ] 验证任务结果
- [ ] 总结经验教训
- [ ] 提交代码
- [ ] 关闭任务

## 异常处理

### 任务阻塞
1. 记录阻塞原因
2. 寻求帮助
3. 调整任务优先级

### 代码冲突
1. 使用 Git 解决冲突
2. 协商解决方案
3. 必要时请求人工介入

### 质量问题
1. 停止提交
2. 修复问题
3. 重新审查
