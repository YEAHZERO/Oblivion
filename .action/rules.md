# 业务规则

## 概述

本文件定义了 alphα 项目中的业务规则和约束条件。所有 AI Agent 都应遵循这些规则执行任务。

## 核心规则

### 1. 代码质量规则

#### 1.1 命名规范
- **文件命名**: 使用小写字母和连字符
- **变量命名**: 使用驼峰命名法
- **常量命名**: 使用全大写和下划线
- **函数命名**: 使用动词开头的驼峰命名
- **类命名**: 使用帕斯卡命名法

#### 1.2 代码风格
- 缩进: 使用 4 个空格 (Python) 或 2 个空格 (JavaScript/TypeScript)
- 行长度: 不超过 120 字符
- 空行: 函数之间空 2 行，类之间空 2 行
- 导入: 按标准库、第三方库、本地库分组

#### 1.3 代码复杂度
- 函数长度: 不超过 50 行
- 类长度: 不超过 500 行
- 圈复杂度: 不超过 10
- 参数数量: 不超过 5 个

### 2. 安全规则

#### 2.1 输入验证
- 验证所有用户输入
- 使用白名单验证
- 长度限制
- 类型检查

#### 2.2 数据保护
- 敏感数据加密存储
- 使用环境变量管理密钥
- 不在代码中硬编码密码
- 使用 HTTPS 传输

#### 2.3 访问控制
- 最小权限原则
- 身份验证
- 授权检查
- 审计日志

### 3. 性能规则

#### 3.1 数据库
- 避免 N+1 查询
- 使用索引优化查询
- 分页查询
- 缓存热点数据

#### 3.2 内存
- 及时释放资源
- 避免内存泄漏
- 使用连接池
- 限制缓存大小

#### 3.3 并发
- 线程安全
- 锁粒度控制
- 异步处理
- 超时控制

### 4. 测试规则

#### 4.1 测试覆盖
- 单元测试覆盖率 > 80%
- 集成测试覆盖率 > 60%
- 端到端测试覆盖率 > 40%

#### 4.2 测试质量
- 测试独立性
- 测试可重复性
- 测试快速性
- 测试可维护性

#### 4.3 测试命名
- `test_<功能>_<场景>_<预期结果>`
- 示例: `test_login_valid_credentials_success`

### 5. 文档规则

#### 5.1 代码文档
- 所有公共函数必须有文档字符串
- 复杂逻辑必须有注释
- TODO 必须有说明

#### 5.2 API 文档
- 所有 API 必须有文档
- 包含请求/响应示例
- 包含错误码说明

#### 5.3 变更日志
- 使用 Conventional Commits 格式
- 记录所有变更
- 包含版本号

### 6. Git 规则

#### 6.1 分支管理
- `main`: 生产分支
- `develop`: 开发分支
- `feature/*`: 功能分支
- `hotfix/*`: 紧急修复
- `release/*`: 发布分支

#### 6.2 提交规范
```
<type>(<scope>): <subject>

<body>

<footer>
```

类型:
- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档更新
- `style`: 代码格式
- `refactor`: 重构
- `test`: 测试
- `chore`: 构建/工具

#### 6.3 代码审查
- 每个 PR 必须有至少一个审查者
- 审查意见必须在 24 小时内回复
- 必须通过所有 CI 检查
- 必须有完整的测试覆盖

### 7. 部署规则

#### 7.1 环境管理
- 开发环境: 本地开发
- 测试环境: 自动化测试
- 预生产环境: 验证
- 生产环境: 正式发布

#### 7.2 发布流程
1. 代码审查通过
2. 测试通过
3. 安全检查通过
4. 性能检查通过
5. 文档更新
6. 版本号更新
7. 部署到生产

#### 7.3 回滚机制
- 保留上一个版本
- 快速回滚能力
- 回滚后验证

## 工作流规则

### 1. 任务执行规则

#### 1.1 任务接收
- 理解任务需求
- 评估任务复杂度
- 确定任务优先级
- 分配任务资源

#### 1.2 任务执行
- 按照工作流程执行
- 记录执行过程
- 遇到问题及时反馈
- 保持与团队沟通

#### 1.3 任务完成
- 验证任务结果
- 更新相关文档
- 记录经验教训
- 提交审查

### 2. 协作规则

#### 2.1 沟通规范
- 使用清晰的语言
- 及时回复消息
- 记录重要决策
- 保持专业态度

#### 2.2 冲突解决
- 协商解决方案
- 寻求第三方帮助
- 必要时请求人工介入
- 记录冲突解决过程

#### 2.3 知识共享
- 记录经验教训
- 分享最佳实践
- 更新知识库
- 组织技术分享

## 质量规则

### 1. 代码质量
- 遵循编码规范
- 通过静态分析
- 通过代码审查
- 通过测试

### 2. 文档质量
- 内容准确
- 结构清晰
- 示例完整
- 定期更新

### 3. 测试质量
- 覆盖率达标
- 测试独立
- 测试可重复
- 测试快速

### 4. 安全质量
- 无高危漏洞
- 依赖项安全
- 配置安全
- 敏感信息保护

---

## 违规处理

### 1. 轻微违规
- 提醒改正
- 记录在案
- 不影响发布

### 2. 一般违规
- 要求修复
- 重新审查
- 可能延迟发布

### 3. 严重违规
- 立即停止
- 修复后才能继续
- 可能回滚版本
