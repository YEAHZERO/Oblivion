# .memory - AI Agent 共用记忆库

## 用途
本文件夹是所有 AI Agent 的共享记忆空间，用于持久化存储项目开发过程中的各种记录和文档。

## 目录结构

```
.memory/
├── README.md              # 本文件
├── TODO.md                # 执行清单（由 .design/ 六份文档汇总）
├── daily/                 # 每日工作日志
│   └── YYYY-MM-DD.md      # 按日期命名
├── review/                # Code Review 日志
│   └── YYYY-MM-DD-<PR或MR编号>.md
├── design/                # 设计文档
│   └── <功能名称>.md
├── release/               # 三级版本分层日志（alpha / rc / patch）
│   ├── README.md          #   分层规则与两条版本轴
│   ├── TEMPLATE.md        #   单条记录模板
│   ├── alpha/             #   增量
│   ├── rc/                #   汇总
│   └── patch/             #   热修
└── specs/                 # 需求规格说明书
    └── <功能名称>.md
```

> `TODO.md` 是从 `.design/` 六份设计文档（架构 + UI 三份 + ERRATA + README）汇总出的
> 执行清单：待裁定项、文档缺陷、Phase 路线、工程债、待实测。**它是本机文件**，
> 因为它引用的大量章节与 ID 只存在于同样不入库的 `.design/`。

## 文件命名规范

### daily/ - 每日工作日志
- 格式：`YYYY-MM-DD.md`
- 示例：`2026-09-08.md`

### review/ - Review 日志
- 格式：`YYYY-MM-DD-<PR或MR编号>.md`
- 示例：`2026-09-08-PR123.md`
- 示例：`2026-09-08-MR456.md`

### design/ - 设计文档
- 格式：`<功能名称>.md`
- 示例：`用户认证模块.md`
- 示例：`支付系统架构.md`

### specs/ - 需求规格
- 格式：`<功能名称>.md`
- 示例：`用户注册需求规格.md`

### release/ - 三级版本分层日志
- 格式：`alpha/v<版本>.md`、`rc/<版本>-rc.<序号>.md`、`patch/<版本>-p<序号>.md`
- 分层规则见 `release/README.md`
- ⚠️ 产品版本记在这里，**设计书版本**记在 `design/architecture.md` §20 —— 两条轴别混

## 使用指南

### 对于 AI Agent

**每轮结束时的固定动作**（三步，缺一不可）——这条是 2026-10-03 补的，因为前几轮只更新了 `TODO.md`：

| 步 | 写什么 | 规则 |
| --- | --- | --- |
| ① | `daily/YYYY-MM-DD.md` | 今日完成 / 进行中 / **遇到的问题**（含「怎么被发现的」）/ 明日计划 / 备注。没有今日文件就按 `daily/TEMPLATE.md` 建 |
| ② | `release/alpha/v<版本>.md` | **改了行为、依赖、持久化格式或 CLI 参数就必须写**。同一版本内未发布的后续增量**追加到同文件**（见 `v0.0.1.md` 的两节先例），不另开版本 |
| ③ | `TODO.md` | 勾掉已做的、补上新增的；轮次要留一段「本轮已执行」 |

对外可读的版本说明写仓库根 `CHANGELOG.md`，**不要**只写在 `.memory/` —— 本目录不入库。

其余惯例：

1. 每次工作开始时，检查 `daily/` 中是否有今日日志
2. 工作过程中，及时更新日志内容
3. 完成 Review 后，在 `review/` 中创建审查记录
4. 设计新功能时，在 `design/` 中创建设计文档
5. 需求规格写进 `specs/`

### 对于开发人员
1. 可以直接编辑 `.memory/` 中的文件
2. 保持日志的连续性和完整性
3. 定期回顾和整理历史记录

## 注意事项
- ⚠️ **本文件夹分两半：规则入库，记录不入库**（根 `.gitignore` 的「本地协作层」段）。
  - **入库**：本 `README.md`、各目录的 `TEMPLATE.md`、`release/` 的分层规则 ——
    它们是「怎么用这个记忆库」的规范，任何机器上都应一致；不入库则每个 agent 各写一套。
  - **不入库**：本机积累的**记录** —— `TODO.md`、`daily/*.md`、`design/*.md`、
    `specs/*.md`、`release/alpha/*.md`。它们随个人与机器而异，入库只会制造噪音与冲突。
  - 需要公开的版本说明写进仓库根的 `CHANGELOG.md`，**不要**只写在本目录 —— 别人看不到这里
- 能被多台机器共用的**设计文档**放入库的 `.design/`，不要放本目录的 `design/`（后者是本地草稿位）
- 敏感信息（如密码、密钥）不要记录在日志中
- 保持文件命名的一致性
- 定期清理过期的临时文件
