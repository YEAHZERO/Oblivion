## 关键发现确认

**`C:\Users\liveu\.dsh`** 是运行时目录（sessions / profiles / storages），**不是源码目录**。源码证据在 `C:\Users\liveu\dev\dsh-ref\versions\0.2.0-rc.2\`。

**品牌槽位的真相：**

| 项 | 事实 |
|---|---|
| `dsh-client-ui-brand-official` host 侧 | `apply() {}` 空函数，只为让 Loader 有一行 |
| 真实注册发生在 **client 侧**（`exports["./client"]`） | `ctx.slots.inject('sidebar.brand.mark', ...)` + `ctx.slots.inject('sidebar.brand.name', ...)` |
| 闸门 | `if (process.env.DSH_CLIENT_BUILD_PROFILE !== 'official') return` — 非 official 构建**不注册**，留位给下游覆盖 |
| Oblivion 现有实现 | `oblivion-web-ui/src/brand/` 已有 `PolarisLogo` / `BrandWordmark`；`slots.ts` 声明了 `sidebar.brand.mark` / `sidebar.brand.name` 两个 single 槽，但**目前没有任何插件去 claim 它们** |

**结论**：品牌化**不需要 Fork**。Oblivion 已经有品牌组件（`PolarisLogo` / `BrandWordmark`）和槽位声明，只需：
1. 写一个 **client-side brand 插件**，`inject: ['slots']`，按 DSH 的模式注册同名槽位
2. 创建一个 **bundle 包**（`oblivion-dsh-bundle`），`cordis.patch.yml` 包含完整组合树

### Phase 1 — `oblivion-brand` 包

**`src/index.ts`**：
```ts
export const name = 'oblivion-brand';
export const inject = ['slots'];  // DSH client 模式：等 slots 就绪

export interface Config {
  readonly label: string;   // "OBLIVION"
  readonly markSize: number; // 24
}
export const DEFAULT_CONFIG: Config = { label: 'OBLIVION', markSize: 24 };

export function apply(ctx: Context, config: Config = DEFAULT_CONFIG): void {
  // 覆盖 DSH 官方品牌插件在 non-official 构建里不注册的空白
  ctx.slots.inject('sidebar.brand.mark', () =>
    ctx.slots.inject('sidebar.brand.name', function* () {
      yield ctx.slots.register({ name: 'sidebar.brand.mark' }, PolarisLogo);
      yield ctx.slots.register({ name: 'sidebar.brand.name' }, () => BrandWordmark({ label: config.label, size: config.markSize }));
    })
  );
}
```

**`cordis.patch.yml`**：bundle 层，默认 `disabled: false`
