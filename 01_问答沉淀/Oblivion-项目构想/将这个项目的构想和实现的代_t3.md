# 项目功能设计分析

## 一、DSH（DeepSeek Harness）—— AI 编程助手平台

### 定位
一套**可编程的编码智能体运行环境**。用户在一个 Web GUI 中与 AI 协作编写代码，AI 拥有终端、文件系统、沙箱等完整工具链。

### 核心架构层

```
┌─────────────────────────────────────┐
│  Browser Client (React)             │  ← UI 层，26 MB bundle
│  - 会话列表 / 对话 / 工具调用展示   │
│  - 终端 / 文件浏览器 / 设置面板     │
│  - 品牌槽位 sidebar.brand.mark/name │
└──────────────┬──────────────────────┘
               │ WebSocket + HTTP /api
┌──────────────▼──────────────────────┐
│  Host / Cordis 容器                │  ← 组合树驱动运行
│  - dsh-base（24 行基础行）          │
│  - dsh-web-app（Web 专属行）        │
│  - 287 个 @deepseek-ai/* 包        │
│  - 六层 YAML patch 叠加引擎         │
└──────────────┬──────────────────────┘
               │ ctx.llm / ctx.session / ctx.tools
┌──────────────▼──────────────────────┐
│  Agent Loop                         │  ← 请求驱动
│  - 接收用户输入 → 构建 prompt       │
│  - 调用 LLM → 执行工具 → 循环       │
│  - 持久化到 session JSONL           │
└─────────────────────────────────────┘
```

### 关键能力矩阵

| 子系统 | 包名 | 核心职责 |
|---|---|---|
| **Agent** | `dsh-agent` / `dsh-agent-loop` | 推理循环：inbox → LLM → 工具调用 → 结果写入 session |
| **LLM** | `dsh-llm` / `dsh-llm-deepseek-api-key` | 多模型适配，API key 从凭据存储读取 |
| **Session** | `dsh-session` / `dsh-session-persistence-jsonl` | 事件流日志（format v4），支持 inbox 投影、工具恢复 |
| **System Prompt** | `dsh-system-prompt` | 多节拼接：persona + policy + tool schemas + sandbox + 变量插值 |
| **Tools** | `dsh-tools` + 各 tool-* 包 | 20+ 工具：bash/pwsh、fs、grep/glob、edit/write、jobs、goal、workflow、subagent… |
| **Sandbox** | `dsh-sandbox` / `dsh-sandbox-local` | 文件读写沙箱、审批策略、观察策略 |
| **UI** | `dsh-client-ui-*`（57 包） | 三栏框架、57 组件、188 图标、427 主题令牌 |
| **品牌** | `dsh-client-ui-brand-official` | `sidebar.brand.mark` / `name` 槽位注入（非 official 构建跳过，留扩展点）|
| **Profile** | `dsh-base` / `dsh-web-app` / presets | 组合树根（base 24 行 + web 扩展 + 3 套 preset 可选）|

### 组合树哲学
- **287 个包**，约 **183 行**组合树
- **六层 patch**叠加（bundle → 用户 → home → 命令行 → 项目 → runtime）
- **service-availability 驱动激活**，声明顺序无语义
- `cordis.yml` 每次启动重写为空，防止组合结果固化

## 二、Oblivion（遗忘）—— 认知增强插件生态

### 定位
**基于 DSH 宿主的自学习知识库插件组**，让 DSH 智能体从每次对话中自动沉淀知识、形成个人认知画像。

### 设计范式（v4.1 关键决策）

```
❌ 旧范式（v4.0 之前）：自建内核 + Electron/Wails + 独立 webserver
✅ 新范式（v4.1，DEC-024）：不 Fork DSH，只做 @oblivion/* 插件
                            宿主 = 上游 @deepseek-ai/dsh
```

### 核心架构

```
┌─────────────────────────────────────┐
│  Browser Client                     │  ← DSH 原生 Web UI + obl-* 令牌覆盖
│  - Polaris 北极星品牌（插槽接管）   │
│  - 问答界面 / 知识库管理 / MD 查看  │
└──────────────┬──────────────────────┘
               │ 复用 DSH 的 /api 通道
┌──────────────▼──────────────────────┐
│  DSH 宿主 + @oblivion/* 插件组     │
│  dsh-base + dsh-web-app             │
│  + oblivion-knowledge               │
│  + oblivion-qa-loop                 │
│  + oblivion-perspective             │
│  + oblivion-graph-growth (占位)     │
│  + oblivion-feedback                │
│  + oblivion-content-creator         │
│  + oblivion-brand                   │
└──────────────────────────────────────┘
```

### 五条认知主线

| 插件 | 能力 | 触发机制 |
|---|---|---|
| **问答闭环** `qa-loop` | 捕获问答 → 四层筛选 → 注入知识库 | 订阅 `session:complete` 事件 |
| **思维激荡** `perspective` | 在回答后补充一个替代视角 | 主动（单问题）/ 深度（连续同维度追问） |
| **图谱生长** `graph-growth` | 问答共现建边、权重累积、双链写回 | 注入知识库时触发 |
| **反馈画像** `feedback` | 点赞/点踩信号累积 → 可注入的统计片段 | `/api/feedback` 端点 |
| **内容创作** `content-creator` | 播客脚本 / 学习指南 / FAQ / 摘要 | 用户显式触发 |

### 关键技术设计

**品牌接管（DEC-025）**：
- `sidebar.brand.mark` / `sidebar.brand.name` 是 DSH 预留的单占 slot
- 非 official 构建下官方插件不注册（留空）→ Oblivion 的 brand 插件以 `priority: -10` 接管
- 零侵入：禁用 plugin 即恢复官方品牌

**知识存储**：
- 一条目一 JSON 文件（`<root>/<id>.json`），时间戳前缀排序
- `inject()` 返回可拼进 prompt 的文本片段（标题 + 正文 + 标签）

**防回灌（RISK-117）**：
- 注入时标记 `source_type: qa_loop`
- qa-loop 只吸收非 `qa_loop` 来源的问答 → 无限循环终止

**六层 patch**（与 DSH 同源）：
- ① 空根 → ② Bundle 层（`@deepseek-ai/dsh-base`）→ ③ 用户层 → ④ Home 层 → ⑤ 命令行 → ⑤′ 项目层（profiles/web 或 desktop）

## 三、两项目关系总结

| 维度 | DSH | Oblivion |
|---|---|---|
| **角色** | 宿主（platform） | 插件组（extension） |
| **核心能力** | Agent 循环、工具链、会话持久化、Web UI | 知识库、问答闭环、思维激荡、反馈画像 |
| **品牌** | DeepSeek（鲸鱼） | Polaris 北极星（插槽接管） |
| **依赖关系** | 独立运行 | 依赖 DSH 宿主（`inject: ['llm', 'session', 'tools']`）|
| **部署形态** | CLI + Desktop（Electron） | 作为 DSH profile 注入 |
| **包数量** | 287 个 `@deepseek-ai/*` | 26 个 `oblivion-*` |
| **实现阶段** | 成熟（0.2.0-rc.2） | Phase 5（骨架就位，核心认知落地） |

**一句话关系**：Oblivion 不做 DSH 的替代品，而是做 DSH 的"认知插件组"——让每次对话不止是一次问答，而是知识的累积。

- 涉及工具: `pwsh`, `read`
