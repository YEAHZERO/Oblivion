## 路径与计划

### 目标路径

```
packages/oblivion-dsh-bundle/     ← 新建：DSH 插件包

├── tsconfig.json
```

### 计划

**Phase 1 — 创建 bundle 包骨架**
1. 建 `packages/oblivion-dsh-bundle/` 目录
2. 写 `package.json`（版本跟随根，peerDependencies 声明 `@deepseek-ai/cordis`）
3. 写 `tsconfig.json`（继承 `../../tsconfig.base.json`）
4. 写 `src/index.ts`（空出口，纯 bundle 定义用）
5. 写 `README.md`

**Phase 2 — 编写 `cordis.patch.yml`**

- `session` → `oblivion-session`
- `session-sqlite` → `oblivion-session-sqlite`
- `knowledge` → `oblivion-knowledge`
- `knowledge-sqlite` → `oblivion-knowledge-sqlite`
- `tool-web-search` → `oblivion-tool-web-search`
- `tool-file` → `oblivion-tool-file`
- `tool-doc-parse` → `oblivion-tool-doc-parse`
- `qa` → `oblivion-qa-loop`
- `perspective` → `oblivion-perspective`
- `feedback` → `oblivion-feedback`
- `ui` → `oblivion-web-ui`
- `content-creator` → `oblivion-content-creator`
- `adapter-dsh` → `oblivion-adapter-dsh`（disabled: true，按需开启）

**Phase 3 — 注册到根配置**
- 加进 `tsconfig.json` references
- 加进 `registry.json` plugins 数组（pluginCount +1）

**Phase 4 — 构建 + 验证**
- `npm run build`
- `npm test`（package-shape + version-consistency）
- 跑 `node apps/cli/oblivion.mjs --dump-config` 验证组合树

### 关键设计决策

| 决策 | 说明 |
|---|---|
| **不继承 DSH 的 DSH 行** | bundle 只做 Oblivion 行；DSH 核心行由 `@deepseek-ai/dsh-base` 负责 |
| **adapter-dsh 默认关闭** | 只有需要让「既有 DSH 插件跑在 Oblivion 上」时才启用 |
| **所有 config 写全量默认值** | patch 是替换不是合并（设计书 §13.3 ①） |
| **版本号跟根 VERSION** | `0.0.2`（与根一致） |
| **bundle 名** | `oblivion-dsh-bundle`（不冲突，DSH 用 `@deepseek-ai/*` 前缀） |

### 不需要做的

- ❌ 不修改 `profiles/desktop/` 或 `profiles/web/`（它们是独立 profile，不是 bundle）
- ❌ 不改 `oblivion-adapter-dsh`（它只做 DSH 命名空间映射，职责清晰）
