# 两个项目功能设计分析（基于实际代码）

## 一、Oblivion（遗忘）—— 基于 WeKnora → DSH 插件化的重构

### 原形态（WeKnora 时代，现仍在孤儿分支）

```
WeKnora (Go + Wails)
├── search.go           # 知识检索引擎
├── md_sync.go          # Markdown 自动落盘
├── qa_loop.go          # 问答闭环
├── perspective.go      # 思维激荡
├── graph_growth.go     # 图谱生长
└── feedback.go         # 反馈画像
```

Go + Wails 是**独立桌面应用**，有自己的 GUI 框架、知识存储、LLM 调用。

### 当前形态（v4.1 宿主化重构后）

**核心范式转变（DEC-024）**：Oblivion 不再是独立应用，而是 DSH 宿主的插件生态。

```
当前仓库实际内容：
├── oblivion-brand/   # ✅ 已实现 —— 品牌槽位接管
├── oblivion-vimc/    # ✅ 已实现 —— Vim 键盘导航
└── 设计书 + Agent 协作框架
```

**设计目标**：利用 DSH 宿主已有的 20+ 项能力（容器、组合引擎、LLM 适配、会话、57 个 UI 组件），只写宿主**没有**的领域能力。

### 两个已落地插件的深度分析

#### ① `@oblivion/brand` v0.1.0

**解决的问题**：DSH 非 official 构建中，`dsh-client-ui-brand-official` 的 `apply()` 因为 `DSH_CLIENT_BUILD_PROFILE !== 'official'` 会提前 return，导致侧栏品牌位空着。

**实现**：
- **Node 半边**（`src/index.ts`）：注册 `POST /obl-brand/restart` 路由
  - 通过祖先进程链上的 `resources\app.asar` 文件标记来**验证身份**（不做进程名启发式）
  - 用 **WMI** 派生游离进程运行 PowerShell 重启脚本（确保不受 Electron Job Object 影响）
  - 重启前先生成 `relauncher.cmd` 后台执行，700ms 后才杀宿主进程
  - 安全边界：验证 Origin 必须是 `dsh-app://app` 或 `127.0.0.1/localhost`
- **Client 半边**：注册 `sidebar.brand.mark` / `sidebar.brand.name` 槽位，用北极星（Polaris）覆盖 DeepSeek 鲸鱼品牌

**设计亮点**：
- `priority = -10` 遮蔽官方品牌（DEC-025）
- 零侵入：禁用插件即恢复官方外观
- 身份验证用**文件存在性**而非进程名（防 `explorer.exe` 误匹配）

#### ② `@oblivion/vimc` v0.2.8

**解决的问题**：DSH 网页端的键盘操作效率。用户需要鼠标滚轮翻页、点击输入框，而 Vimium-C 的键位在 Windows/macOS 桌面端会被**原生层抢先拦截**。

**实现**：
- **纯 DOM 层**：直接监听 `window` 的 keydown 事件，不走 DSH `ctx.shortcuts`
- **焦点感知**：焦点在 `<input>` / `<textarea>` 内时完全不接管（一个键都不拦截）
- **键位体系**：
  | 键 | 动作 |
  |---|---|
  | `w/s` | 上/下翻页（0.6 屏） |
  | `a/d` | 横向像素步进 |
  | `W/S` | 到顶/到底 |
  | `[` / `]` | 上一条/下一条提问 |
  | `/` | 页面内查找（`.`,` `前后跳） |
  | `f` | 链接提示（单字母标记） |
  | `i` | 聚焦输入框 |
  | `Esc` | 退出输入框 |
- **渐进注入**：设置页用 `ctx.inject(['slots'], ...)` 渐进注册，不影响无设置面板的精简场景
- **性能可自证**：候选扫描 7.5–19ms，按键平均 1.8ms；自带 `/oblivion-vimc/beat` 心跳证据端点

**来源**：键位解析器直接从 [Vimium-C](https://github.com/gdh1995/vimium-c) 的 `vimium_c-*.json` 配置导入，但做了适配决策（见 README 里的采纳/未采纳列表）。

## 二、DSH（DeepSeek Harness）—— AI 编程助手平台

### 架构分三层

```
┌──────────────────────────────────────────────────────────┐
│ Browser Client (~26 MB bundle)                           │
│  React + 57 组件 + 427 主题令牌                           │
│  - 对话 / 终端 / 文件浏览器 / 设置面板                    │
│  - 品牌槽位（sidebar.brand.mark / name）                  │
│  - 键盘导航扩展点（oblivion-vimc 挂在这里）               │
└─────────────────────┬────────────────────────────────────┘
                      │ WebSocket / HTTP /api
┌─────────────────────▼────────────────────────────────────┐
│ Host / Cordis 容器                                        │
│  dsh-base（24 行基础层）                                  │
│    ├── llm → dsh-llm-deepseek-api-key                   │
│    ├── session → dsh-session-persistence-jsonl           │
│    ├── agent → dsh-agent-loop                            │
│    ├── system-prompt（多节拼接引擎）                      │
│    ├── tools（20+ 工具：bash/pwsh/fs/grep/edit/jobs…）    │
│    ├── sandbox（审批策略 + 观察策略）                     │
│    └── typert（API schema registry）                     │
│  dsh-web-app（Web 专属扩展 + 3 套 preset）               │
└─────────────────────┬────────────────────────────────────┘
                      │ ctx.* 服务面
┌─────────────────────▼────────────────────────────────────┐
│ Agent Loop（请求驱动推理循环）                             │
│  inbox → LLM → 工具执行 → 结果写入 session JSONL          │
│  - 8KB prompt 上限（agent-instructions）                  │
│  - compaction 压缩（basic + result-pruner）               │
│  - plan mode / subagent / workflow 隔离组                 │
└──────────────────────────────────────────────────────────┘
```

### DSH 与 Oblivion 的关键交互点

| DSH 扩展点 | Oblivion 插件利用方式 |
|---|---|
| `sidebar.brand.mark/name` 槽位 | `@oblivion/brand` 客户端半边 `ctx.slots.inject()` 覆盖 |
| `settings.section` 槽位 | `@oblivion/vimc` 客户端半边注册设置页 |
| `/api/*` HTTP 路由 | `@oblivion/brand` 的 Node 半边 `ctx.webServer.register()` |
| `ctx.slots` 服务 | 两个插件都用，渐进式依赖 |
| `DSH_CLIENT_BUILD_PROFILE` | brand 插件利用非 official 构建跳过官方品牌的特性 |

## 三、两者关系总结

```
WeKnora (Go+Wails)              DSH (TypeScript+Electron)
      │                                │
      │  范式修正 DEC-024               │
      ▼                                ▼
  Oblivion 插件生态             DSH 宿主（不变）
  @oblivion/brand              287 个 @deepseek-ai/* 包
  @oblivion/vimc               24 行基础 + 183 行组合树
  （未来）@oblivion/knowledge   Cordis DI 容器
  （未来）@oblivion/qa-loop     YAML 六层 patch 叠加
  （未来）@oblivion/perspective
  （未来）@oblivion/feedback
  （未来）@oblivion/content-creator
```

**核心洞察**：Oblivion 不是"把 WeKnora 改写成 TypeScript 插件"，而是**放弃了 WeKnora 的知识库内核**，只保留了两个"宿主没有的交互增强"（品牌视觉、键盘导航），其余认知能力（知识存储、问答闭环等）留到后续 Phase 再写。这是 DEC-024 的范式修正——不重造宿主已有的 20 项能力，只做增量。

- 涉及工具: `pwsh`, `read`
