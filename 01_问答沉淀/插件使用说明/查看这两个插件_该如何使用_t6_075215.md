**它做的事**：绕过 DSH 的插件路由，直接带密钥调搜索 API。所以它同时是「密钥还在不在」和「网络真通不通」的探针——重装 `dsh-free-search` / `dsh-web-search-pro`、换引擎、改 profile 补丁之后，比在 DSH 里反复试 `web_search` 快得多。

```powershell
powershell -NoProfile -File tools\key-search.ps1 -KeyStatus                          # key 有没有、来自哪一层（不联网）
powershell -NoProfile -File tools\key-search.ps1 -Query '关键词' -Provider all -N 5   # exa+tavily+firecrawl 并发，按 URL 去重
powershell -NoProfile -File tools\key-search.ps1 -Query '关键词' -Text -MaxChars 4000 # 取页面正文
```

- `-Provider`：`exa` / `tavily` / `firecrawl` / `all` / `opencode`（默认 exa；`opencode` 转发给 `opencode api post /api/websearch`，返回带 `content` 正文）
- 其它参数：`-N`(1–50)、`-Json`（stdout 只有 JSON，可管道）、`-MaxChars`、`-NoSnippet`、`-TimeoutSec`、`-ExaApiKey`/`-TavilyApiKey`/`-FirecrawlApiKey` 覆盖
- 退出码：`0` 有结果 / `1` 引擎失败或零结果 / `2` 用法错误
- 环境变量名与 `dsh-free-search/lib/index.js:2903-2921` 的引擎→环境变量映射保持一致，插件怎么换都读同一批 key

**最关键的一处设计**：读 key 顺序 = 显式参数 > **User 注册表** > Machine > Process。User 排最前，正是因为 DSH 给 agent shell 做了脱敏——会话里 `$env:EXA_API_KEY` 是空的，只有 `[Environment]::GetEnvironmentVariable('EXA_API_KEY','User')` 拿得到。key 值全程不打印，只打印来源与长度。
