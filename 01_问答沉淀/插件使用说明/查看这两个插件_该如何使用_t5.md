## 问题

我还是需要使用密钥进行搜索：key 有效，搜索成功（Exa API https://api.exa.ai/search，header x-api-key）。
你自己读取密钥
密钥存在用户级环境变量里，任何一个都可以：
# 方式1：PowerShell（推荐，当前会话）
$env:EXA_API_KEY

# 方式2：读注册表持久值（新进程也能拿到）
[Environment]::GetEnvironmentVariable('EXA_API_KEY','User')

# 方式3：cmd
echo %EXA_API_KEY%

# 方式4：WSL Debian 里（如果你的 WSL 也配了）
printenv EXA_API_KEY
四个可用 key 的变量名：
Provider	变量名	端点
Exa	EXA_API_KEY	POST https://api.exa.ai/search
Firecrawl	FIRECRAWL_API_KEY	https://api.firecrawl.dev
Tavily	TAVILY_API_KEY	POST https://api.tavily.com/search
Agnes	AGNES_API_KEY	—
两种使用方式
A. 直接调用 OpenCode 的搜索接口（会自动选 provider、处理密钥）：
opencode api post /api/websearch -d '{"query":"你的关键词","providerID":"exa"}'
B. 在自己的代码里用 key 直接调 Exa（就像我上面演示的）：
$h = @{ 'x-api-key' = $env:EXA_API_KEY; 'Content-Type'='application/json' }
$body = @{ query='关键词'; numResults=5 } | ConvertTo-Json
Invoke-RestMethod -Uri 'https://api.exa.ai/search' -Method Post -Headers $h -Body $body
Python 示例：
import os, requests
r = requests.post("https://api.exa.ai/search",
    headers={"x-api-key": os.environ["EXA_API_KEY"]},
    json={"query": "关键词", "numResults": 5}, timeout=20)
print(r.json()["results"])

## 对 DSH 侧的含义

- **DSH 自己是有这些 key 的**：它的 host 进程不是脱敏的（脱敏只作用于给 agent 的 shell），旁证是 `web-search-pro` 的 `sources.status` 报 `exa credential=configured`、`tavily credential=configured`，而它读 key 的方式就是 `lib/engines.js:69` 的 `deps.exaApiKey || process.env.EXA_API_KEY`。
- **但我的 `web_search` 工具走的是 free-search**（当前 mode=bing），它给 exa 留了无 key 的 Exa MCP 兜底通道，所以那条路「能搜」不代表「走了密钥」——这正是我上次提醒的点，现在有直连结果做对照组了。
- 要**确定走密钥**，最稳的是不经插件路由：注册表读 key → 直连 API（或走 opencode 的方式 A）。

## 我接下来的默认做法

需要「一定用密钥」的检索时，我就用 **方式 2 读 key + 直连 Exa/Tavily/Firecrawl**（或 `opencode api post /api/websearch`），输出只回结果、不回 key；要 DSH 原生工具时，用 `advanced_search engine=exa` 显式指定。
