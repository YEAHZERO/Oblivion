## 1. 内核改成共用本机 Edge ✅（写入 profile 补丁）

在 [cordis.patch.yml](C:\Users\liveu\.dsh\profiles\desktop\cordis.patch.yml) 末尾新增了浏览器条目的配置行（Host 的 Settings 服务约定：`- id: browser` 顶层行 + `config`，与插件自带 insert 行同一个 id，`SETTINGS_NAMESPACE = 'browser'` 已核对）：

```yaml
- id: browser
  name: "@anweat/dsh-browser"
  config:
    channel: msedge            # ← 不再用插件自带的 chromium-1243
    authProfiles: { zhihu: …, weibo: … }
```

依据：`dsh-browser/lib/browser-service.js:400-404` 把 `config.channel` 直接传给 `chromium.launch()`（`executablePath` 也可，但 `channel: msedge` 更干净——本机 Edge 在 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`）。改完 YAML 校验通过：**11 entries**（`… web-search-free, web-search-pro, web, browser`）。

## 2. zhihu/weibo 登录态 + browserBindings ✅

- 新写了采集脚本 [dsh-browser-login.mjs](C:\Projects\Oblivion\tools\dsh-browser-login.mjs)：用 dsh-browser 自带的 playwright 以 **Edge 有头窗口**打开登录页，等你扫码/输账号，命中会话 cookie 后自动写出 storageState 并关窗。
  ```
  node tools/dsh-browser-login.mjs zhihu
  node tools/dsh-browser-login.mjs weibo
  ```
- 采集结果（两次都是你登录后自动落盘）：
  - [zhihu.json](C:\Users\liveu\.dsh\data\dsh-browser\auth\zhihu.json) 88557 B，43 cookie / 2 origins，含 `z_c0@.zhihu.com`
  - [weibo.json](C:\Users\liveu\.dsh\data\dsh-browser\auth\weibo.json) 4269 B，12 cookie / 2 origins，含 `SUB@.weibo.com`、`SUBP@.weibo.com`
- 同时给 web-search-pro 加了绑定：`config: {registerProvider: true, browserBindings: {zhihu: {authProfile: zhihu}, weibo: {authProfile: weibo}}}`。这一侧**已经热生效**：`sources.status` 现在报 `platform zhihu: credential=configured health=ready`。

## 3. 为什么还差重启（实测证据）

`web_call search.run platform=zhihu` 目前仍返回：


即 web-search-pro 已经把 authProfile 传过去了，但 **dsh-browser 说自己没有这个 profile** —— 源码注释写得很明确（`@anweat/dsh-browser/lib/index.js:51-52`）：*"resolveConfig reads them once here, so a saved value applies when the profile restarts. Only `prompts` is read live."* 我顺手杀掉旧的 chromium 进程再试，依旧同样报错 ⇒ 配置在插件 apply 时就被固化了。
