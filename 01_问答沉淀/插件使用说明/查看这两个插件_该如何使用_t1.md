## 二、三处修正

**① `fetchProvider: http` 只是"保留宿主抓取"的变体，不是推荐值**

README 推荐两个都指向插件：

```yaml
- id: web
  name: '@deepseek-ai/dsh-web'
  config:
    searchProvider: web-search-pro
    fetchProvider: web-search-pro
```

写 `http` 的后果是：`web_fetch` 仍走宿主自带的裸 HTTP 抓取，拿不到插件的分块裁剪和 `[Continue with ... offset=N]` 续读提示——而"省上下文"恰恰主要靠这条抓取管线。**`fetchProvider` 确实不能省**（插件同时注册 search + fetch 两个 provider，省略后宿主的 `http` 与插件的同时可用 → `WEB_PROVIDER_AMBIGUOUS`），但值该填 `web-search-pro`。（`http` 这个 id 是 README 自己标注的"以所用宿主版本为准"的内置值，我在本机 host 包里只确认了 `searchProvider`/`fetchProvider` 两个字段本身，没确认到 `http` 的注册点。）

**② `provider: {evidence: auto}` 是默认值，写了等于没写**

源码里 `evidence` 本来就是 `default('auto')`，`providerId` 默认就是 `web-search-pro`。所以真正的开关**只有 `registerProvider: true` 一个**。

**③ 本机没有 `settings.yaml`，"改 settings.yaml"是新建文件**

`C:\Users\liveu\.dsh\` 下只有 `settings.yaml.imported`，内容只有 2 行（`ui-onboarding`）——原文件被核心导入后改名了。所以照抄"改 settings.yaml"在本机是**新建**。更稳的路径是走面板：**设置 → 插件 → 插件配置 → Web Search Pro**，打开 `registerProvider`（中文本地化标签就是「注册为 ctx.web Provider」），保存后它自己写文件并热更新。

## 三、结论

那份说明的最终建议——**保持现状**——我同意，理由也成立：free-search 的引擎面（21 个引擎可切、中文优化、免费兜底）比 web-search-pro 的窄引擎列表宽得多，日常搜索没理由换；而证据包（`task`/`profile` → `gaps` + 带引用的摘录 + 字符预算）只在深度调研时才有价值，那时我直接调 `web_call search.run` 就行，不接管也能用。

接管的唯一收益是**内置 `web_search` / `web_fetch` 自动走证据管线**（不用我每次记得手写 `web_call`）。代价是 free-search 退居二线，只剩 `advanced_search` / `multi_search` / `platform_search` / `video_search` / `free_search_test` 这几个工具在用。两者不冲突，只是"谁占宿主的坑"二选一。
