## 写进文档的几个关键结论

1. **只有进 `dsh.profile.bundles` 的包才会被加载** —— 这是"装了没反应"的头号原因。
2. **两条挂载路径**：bundle 层（改一次要重启）vs 热挂 insert 行（补丁层被监视、客户端不用刷页面）。热挂型（core/panel/http-bridge/vimc）**缺 profile 那行就会静默失效、不报错**。
3. **五条真实协作链**：面板协议（`ctx.provide` + `render`）、侧栏座位链（`ctx.betterSidebar.registerTab`）、认知层三段式（core → http-bridge 消费 `oblivion` 服务 / panel 只读落盘文件，所以两者互不牵连）、压缩与 provider 无关（billion-context 在 agent loop 层，覆盖 deepseek-web 会话）、搜索两层分工（free-search 运行时接管、web-search-pro 默认只给 `web_index`/`web_call`）。
4. **两处待实测风险**：`billion-context` 劫持 `globalThis.fetch`（`dsh-native.js:132`）与 `dsh-deepseek-web-login` 直连 `chat.deepseek.com` 是否互相改道**没有判定证据**；端口 **42081** 被 `@oblivion/http-bridge` 固定占用，而旧 `web` profile 的启动日志里正是 `webserver EADDRINUSE 127.0.0.1:42081`。
5. **原生压缩关不掉**（上游 issue #1772）：`dsh-web-app` 的 preset 自带 `compaction-basic`，billion-context 的补丁设不动 → 本机两套压缩并存，属正常。
6. **两个本机补丁升级会丢**：`dsh-creator-mode-plus`（`src/desktop-profile.js` 的 `installAnchor` 反斜杠、`src/runner.js` 的 `pathToFileURL`）与 `dshmarket`（`lib/hot.js:161`，重打脚本 `tools\patch-dshmarket-hot-id.ps1`）。
7. **文档与实现不一致 4 处**已在 §6.6 列出（如 `dsh-deepseek-chat` README 写的命名空间 `dsh-deepseek-chat` 与代码里的 `dsh-chat-entry` 不符）。
