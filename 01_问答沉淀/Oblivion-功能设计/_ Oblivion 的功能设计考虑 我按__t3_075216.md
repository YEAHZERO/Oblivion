## 一、核心认知功能（"自学习"三组件 + 反馈）

这是 Oblivion 区别于普通 RAG 的根本。

### 1.1 问答闭环（REQ-004~006）

| 设计考虑 | 具体做法 | 为什么这么设计 |
|---|---|---|
| **问答即沉淀** | 每次问答完成后自动捕获「问题 + 答案 + 引用」 | 让知识库随使用自然生长，不用人工整理 |
| **四层筛选** | L1 精确去重（SHA256）→ L2 语义去重（hybrid-search >0.85）→ L3 基础规则 → L4 价值评估 | 分层过滤：便宜的（哈希）先跑，贵的（LLM）后跑 |
| **L3 阈值中文适配** | 从"答案 <10 字"改为"**<5 字或仅含无意义词**" | 中文一个字信息量大，"用 pgvector"（11 字符）其实是有效答案，原阈值会误杀 |
| **L4 首版纯规则** | 不引入外部评估 API | 单机自用场景，用户即评估者；引入外部 API 增加依赖成本 |
| **注入走 Manual** | `POST /knowledge/manual`，Markdown body | 路径确定、权限明确，与 `md_sync` 配合最好 |
| **防回灌死循环（RISK-117）** | `source_type: qa_loop` 豁免标记，`qa_loop` 来源的知识跳过下一轮捕获 | 否则"问答沉淀 → 注入知识库 → 又被捕获"会无限循环 |

### 1.2 思维激荡（REQ-014）

| 设计考虑 | 具体做法 | 为什么这么设计 |
|---|---|---|
| **双模式触发** | 主动触发（单次提问后自动附加 1 个新视角）+ 深度触发（连续 ≥3 次追问同维度 → 生成 ≥3 候选） | 主动模式体现"认知陪伴"；深度模式在用户卡住时出手 |
| **触发闸门精细** | 主动：会话 ≤3 次 + 问题 ≥10 字 + 必须有引用 | 防止无价值触发（如"你好"）、防止打扰 |
| **四策略落地** | 时间拉伸 / 对立视角 / 角色扮演 / 边界测试 | 每种策略有明确的触发场景，不泛泛而谈 |
| **必须可关闭（AC-020）** | 未加载插件即完全无开销 | 保底验收：用户有完全的控制权 |
| **单会话上限** | `OBLIVION_MAX_STIMULATIONS_PER_SESSION=5` | 防噪音（RISK-019） |
| **输出走流内事件** | `session:thinking` 事件 + `ext_think` 渲染，不混入主回答 | 参考 DSH 的 `thought` 事件先例，天然异步 |

### 1.3 图谱生长（REQ-015）

| 设计考虑 | 具体做法 | 为什么这么设计 |
|---|---|---|
| **共现建边** | 问答引用了哪些文档，这些文档两两建边 | 借鉴 KnowledgeX「问答即生长」 |
| **权重规则精确** | 0.3 起步 / 每次共现 +0.05（cap 1.0）/ 30 天未更新 ×0.95 衰减 | 防权重膨胀；30 天衰减模拟知识遗忘 |
| **双链写回** | `[[目标文档标题]]` 追加文末 | 与 Obsidian 语法兼容，可在 Obsidian 中直接打开 |
| **首版不动 search.go** | 图增强检索后置 | 沉淀知识后上游混合检索天然能命中，"图增强"是锦上添花 |
| **降级策略** | Neo4j 不可用 → 只写 `oblivion_cooccurrence_edges` 快照表，MD 双链不写 | 主问答链路零影响 |
