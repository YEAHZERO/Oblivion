## 1. 落点框错位：根因找到了，已修

你说的「搜『高亮』，黄框出现在『结果』旁边」是**坐标过期**：

| | 之前（错） | 现在（对） |
| --- | --- | --- |
| 画框时机 | **先画框、后滚动** | **先滚动、再画框** |
| 用的是什么坐标 | 视口坐标，画完就固定 | 视口坐标，但**存活期一直重摆** |
| 滚动（尤其平滑滚动动画）时 | 文字走了、框留在原地 → 差一两行 | 监听 `scroll`/`resize`（捕获 + rAF 节流）**跟着走** |

寿命也从 900ms 提到 1200ms（够覆盖平滑滚动动画），自检新增 `find.repositions`（重摆次数）——这类「对齐」问题以后能直接从证据文件看出来。

## 2. 读了 vimium-c 源码（`C:\Projects\SourceCode\vimium-c-master`）

先说一件**必须纠正的事**：vimium-c 的许可证是 **Apache-2.0**（`LICENSE.txt`：Copyright 2023-present Gong Dahan），我之前 README 里写成 MIT 是错的，已改正，并补了一张「读了哪个文件 / 复用了什么 / 哪里故意不一样」的对照表：

| 上游 | 复用 | 我们的差异（保留本插件 UI） |
| --- | --- | --- |
| `hint_filters.ts` | 提示串**短在前**的分配思想 | 上游遇到「完整匹配又是别人前缀」时**等 255ms 定时器**消歧；我们**保留首字母**给两位串，所以单字母**立即触发**、不等待 |
| `dom_ui.ts` `flash_()` | 矩形**落点标记**、同时只留一个活动标记、有寿命并淡出 | 上游能把矩形换算成页面坐标（`.AbsF`）；DSH 正文是**嵌套滚动容器**、不能假定宿主定位上下文 → 我们用「跟随重摆」 |
| `mode_find.ts` | 大小写、`postOnEsc`（Esc 后查询仍可用）、反向查找、把命中矩形闪一下（~2.4s） | **不用 `window.find`**：它会接管原生选区，而 DSH 输入框是 Lexical 宿主，外部动选区会让编辑器状态与 DOM 失步 |
| `link_hints.ts` | 可点击元素口径、可见性过滤 | 额外做了**三档优先级**（下面这条） |

## 3. 内联引用单独一档（排在消息操作按钮之前）

判据来自你那张悬停截图：**内联引用悬停时显示它指向的文件路径**，所以它的 `title`/`aria-label` 里就是引用目标。于是：

| 档 | 判据 |
| --- | --- |
| ① **内联引用** | 真链接（`a[href]`/`role=link`/`data-href`），或 `title`/`aria-label` **含 `/`** / **以 `@` 开头** / **以已知文件扩展名结尾**（`oblivion-vimc/README.md` 这类） |
| ② 正文其它 | 消息操作按钮（复制/引用/重新生成）、`summary`、`[tabindex]` |
| ③ 外部 | 侧栏/工具栏/输入区 —— 永远最后 |

- **判据刻意收紧**：我第一版用了宽泛的「点 + 短串」，真机上把一个 `aria-label` 带 `deepseek-v4.1` 的按钮误判成引用了；现在只有「路径分隔符 / `@` / 已知扩展名」才算，版本号不会误判（已写成正反例测试）。
- **真机实测**：`tiers { references: 1, content: 25, outer: 20 }`、信号 `path` —— 视口里那 1 个真·文件引用被单独提到最前拿到单字母，消息操作按钮其后，外部 20 个最后 ✓
- 顺带回答你的问题：**`@oblivion/brand` 是你们仓库里的一个插件包名**（品牌插件，按设计书占 3 个品牌槽位），`@` 只是包名前缀；你截图里悬停弹出的 `oblivion-vimc/README.md` 说明这个 chip 是**指向文件/文档的内联引用**（不是浏览器链接）—— 也就是现在被单独提前的那一类。
