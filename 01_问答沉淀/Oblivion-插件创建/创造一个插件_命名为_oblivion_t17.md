## 一、范围：不是「只在那个目录里」，而是**该 profile 里的每一轮问答都进判定**

| 问题 | 事实（代码取证） |
| --- | --- |
| 触发范围 | 插件是 **Host 侧、profile 级**：`ctx.on('session/event')` → **任何一轮问答的 `turn/end` 都会进判定**。代码里**没有任何工作目录 / workspace / 会话过滤** |
| 生效范围 | **只在你装载了它的 profile**（现在只有 `desktop`）。换用别的 profile（例如 CLI）不生效 |
| 你设的目录是什么 | **只是笔记的落点**（`mdRoot`），**不是捕获范围**。`dataRoot`（`~/.oblivion/data`）同样是全局的，不分会话/项目 |
| 是不是「都会自动沉淀」 | **不是**。每一轮都进四层筛选，但**只有过关的才沉淀**：<br>① 必须有**真人提问**（`user/message` 且 `source.kind === 'user'`）——`agent.inject` 注入的上下文、纯工具轮、定时唤醒轮**不算**（记为 `no-qa`）<br>② L3 四条规则（<5 字 / 无意义词 / 开头「不知道」/ 纯寒暄）<br>③ L1/L2 去重与冲突<br>④ L4 价值分 **≥ 0.30** |

所以准确回答你：**全 DSH（该 profile）的问答都会被「看一眼」，只有高价值的才落进你那两个目录**。如果你想要「只在某目录里工作时才沉淀」，那是一行过滤（可以加 `captureOnlyInWorkspaces`）——但建议**先靠数据决定**（见第三节），别凭感觉收窄。

## 三、「获取需要修改的参数」的完整闭环

```
① 感知：oblivion_status（或直接看 status.json / decisions.jsonl）
        ↓ 返回 hints: [{ key, current, suggested, why }]
        例：{ key: 'valueThreshold', current: 0.3, suggested: 0.25,
              why: '捕获率 0.03，且 78% 被价值层拦下 —— 阈值偏高' }
② 修改：%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml 的 insert 行里补 config:
        ↓ 补丁层被监视，改 config 落盘即生效（改 JS 代码才需要重启 App）
③ 再过几天：回到 ①
```

**建议的两条边界**（就是防「拿三四轮数据瞎调」）：可评估轮 **<20 不开口**；当主要拦截原因是**完全重复**时，它**明确告诉你不用调**；只有在**阈值正落在分值分布中央（±0.05）**时才建议动。

实测一次完整输出（自检里的真跑）：

```
判定留痕：留痕 4 条 / 动作 created,duplicate,no-qa / 每条都有 reason 与耗时
观测面：  配置项 31 个 / 建议 0 条（样本不足，刻意不开口）/ 最近 4 条
建议边界：样本不足=0 条 / 低捕获=2 条 / 重复=1 条（无 suggested）
```
