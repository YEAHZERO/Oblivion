## 四、现在唯一值得**预判**的参数（纯代码推导，不靠数据）

陪伴功能的第一道门不是「遗漏维度」，而是**档案置信度**：

```
perspective.onTurn →  if (profile.inquiry_style.confidence < 0.3) return   ← 第一道门
档案置信度 = min(0.5, 命中的维度关键词组数 × 0.15)          （src/profile/index.ts）
维度关键词组 = 为什么/原理 · 怎么/步骤 · 选/对比 · 风险/坑 · 设计/架构
```

推出来的结论很具体：

| 情形 | 后果 |
| --- | --- |
| 问题里**同时含 ≥2 类**关键词（例：「**为什么**这样设计，有**风险**吗」） | 置信度 = 0.30 → **恰好过门**，档案开始累计，陪伴才有机会开闸 |
| 问题只含 **1 类**（例：只问「为什么…」） | 置信度 = 0.15 < `CONFIDENCE_FLOOR 0.3` → **档案根本不更新**，`sessions_observed` 也不涨 → 陪伴永远不动 |

所以如果你平时问得短、只含一类关键词，**几天后最可能看到的是** `perspective.queued == 0` 且 `profile.confidence == 0`。那时的选择就两条，都写在明处：

| 选项 | 改法 | 代价 |
| --- | --- | --- |
| **A. 降陪伴闸门**（一行 config，热挂即生效） | `perspectiveMinConfidence: 0.3 → 0.15` | 1 类关键词就开闸，更容易打扰 |
| **B. 降档案地板**（代码改动，要重启） | `CONFIDENCE_FLOOR` 或 `hits × 0.15` 的权重 | 改动进内核，影响所有依赖档案的路径 |

**但我建议现在两条都别动** —— 你说的「先跑够几天」是对的，而这个预测本身可以在数据里被证伪。
