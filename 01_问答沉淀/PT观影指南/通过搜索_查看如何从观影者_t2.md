## 问题

这两个插件是如何使用的？：dsh-web-search-pro和dsh-free-search

## 回答

## 结论

两个插件是**分层互补**的：`dsh-free-search`（0.9.1）是**引擎层**——把 20+ 免费/付费搜索引擎打包成一系列小工具（`web_search`/`web_fetch`/`advanced_search`…），带自动回退链，零成本开箱即用；`dsh-web-search-pro`（0.2.1）是**研究管线层**——用 `web_index` + `web_call` 两个工具提供"证据包"式调研（按需求过滤摘录、持久化历史、可选浏览器渲染），上下文占用远小于裸搜+裸抓。两者可共存，本会话里都已安装生效。

## 对照

| 维度 | dsh-free-search | dsh-web-search-pro |
| --- | --- | --- |
| 定位 | 多引擎搜索 provider + 网页抓取，永不直接失败（自动回退） | 一次调用完成研究：搜索→重排→分层抓正文→证据包 |
| 工具形态 | 一堆独立小工具 | 只有 `web_index`（能力索引）+ `web_call`（执行动作）+ 随包 skill `dsh-web-search-pro` |
| 输出 | 结果列表（候选 url/title/snippet） | 证据包（按 need 过滤的段落摘录 + `gaps` 缺口 + `history.expand` 展开） |
| 缓存 | 相同查询 5 分钟 LRU 结果缓存 | SQLite 持久历史/正文缓存（7 天，`cache_search` 可回查） |
| 浏览器能力 | 无 | 集成 `@anweat/dsh-browser`：Playwright 快照、登录态平台（知乎/微博/贴吧…）、OpenCLI |

## dsh-free-search 怎么用

安装即用（`dsh plugin --profile web add` 后重启），它自动接管 `web` 搜索 provider：

| 工具 | 用途 |
| --- | --- |
| `web_search` | 首选引擎 + 统一回退链（首选→其他→免费兜底），失败按类冷却，搜索不直接挂 |
| `web_fetch` | 抓网页全文（HTTP provider，自动跟重定向、截断提示） |
| `advanced_search` | 显式指定引擎 + `timeRange` 时间过滤（`day/3d/2mo/2026-07-01`） |
| `multi_search` | 按语言池并发全部启用引擎，eTLD+1 去重合并，跨源命中置顶 |
| `platform_search` | 单站点搜：GitHub/B站/Reddit/V2EX/HN/StackOverflow/YouTube/Vimeo/掘金/豆瓣等 |
| `domain_search` | 41 个免 key 垂直源直查：包版本、arXiv/Crossref、CVE/NVD、金融/外汇、法律、新闻 |
| `video_search` / `weather` | 跨站找视频 / 天气 |
| `free_search_test` | 一键体检所有引擎（区分 quota/auth/反爬/瞬时失败） |

操作入口：
- 聊天框 `/free-search-engine` 弹出选引擎（等效设置页切换+保存）；
- 左侧「插件」页 → `free-search` → `web-search-free` 行配置：切引擎、填 API key、勾选启用引擎、调回退顺序、Multi 模式三档强度；
- 配置写在当前 profile 的 `cordis.patch.yml`（`web-search-free` 条目 `config`），key 建议放凭据中心 `~/.dsh/.credentials.yaml`。
- 当前状态：首选 `bing`，启用 10 个引擎，安全搜索 off。

## dsh-web-search-pro 怎么用

常驻只有两个工具，用法是"索引→调用"：

1. `web_index` 不传参 = 能力组目录；`{group}` 列动作；`{action}` 给完整参数 schema；
2. `web_call({action, args})` 执行动作，分组：
   - `search.run`：核心。传 `query` 就是普通搜索；传 `task`（一句话目标）或 `profile`（`docs_code/news_fact/academic/experience/compare`）变**证据包**：按需求读前 4 页正文、分块评分、预算内挑摘录，并列出未满足的 `gaps`；可加 `needs`（子问题）、`constraints`（`{kind,value,strength}`，如 `site:hard`）、`budget`、`engines`、`platform`；
   - `search.recommend`：按任务最多推荐 3 个就绪来源（不发搜索请求）；
   - `read.fetch`：可读化抓取（Jina→HTTP 规则→Playwright 升级），长页 `offset` 续读命中快照缓存；
   - `read.contents` / `read.snapshot`：Exa 批量正文（需 key）/ 浏览器快照落盘；
   - `history.list|replay|expand|export|delete`：持久历史与证据摘录回读；
   - `sources.status|deps|install`：后端就绪体检、依赖安装；
   - `rules.*` / `cache.*`：按站提取规则与缓存管理。

两种接法（README「两种用法」）：
- **(a) 直接调** `web_call search.run`——做联网调研时优先于 `web_search`+`web_fetch` 手动串；
- **(b) 接管宿主工具**：`settings.yaml` 里 `web-search-pro: { registerProvider: true }` + profile 的 `cordis.patch.yml` 里 `web.searchProvider: web-search-pro`（必须连 `fetchProvider` 一起写），这样模型"顺手"调内置 `web_search`/`web_fetch` 时也走它的证据管线（`provider.evidence: auto`）。

> 注意版本线：0.2.x 只支持宿主 DSH ≥0.2.0-rc.2 且旧 dsh-browser 0.1.x 不支持（浏览器能力会报 `CAPABILITY_UNAVAILABLE`，其余照常）；还在 0.1.x 宿主上请停留 0.1.15。
