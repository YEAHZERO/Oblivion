## 结论

脚本里的地址已查到：**CDP = `http://127.0.0.1:9222`**（`/json/version` 验证），Edge 可执行文件 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`，调试档 `%LOCALAPPDATA%\Microsoft\Edge\UserDataDebug`。但源码核对后发现关键事实：**dsh-browser 0.2.1 不支持"挂到已运行的 9222 实例"（没有 connectOverCDP），而且它本来就不需要装 Chromium——你的 patch 里 `channel: msedge` 已让 playwright 直接启系统 Edge**。我把配置改成"复用同一个调试档"，这是最接近你 edge mcp 连接的效果。

## 事实核对（dsh-browser 源码）

| 点 | 证据 |
| --- | --- |
| 不用装 Chromium | [browser-service.js:1529](node_modules/@anweat/dsh-browser/lib/browser-service.js#L1529)：只有 `channel==='chromium'` 或显式 `executablePath` 才报"Expected Chromium executable is missing"；`channel: msedge` 走系统 Edge，`%LOCALAPPDATA%\ms-playwright` 里那份 310MB 只是兜底（你 patch 注释也这么写） |

| `args` 可传启动参数 | [config.js:117](node_modules/@anweat/dsh-browser/lib/config.js#L117) `args: string[]` "Additional Chromium CLI launch arguments"，可塞 `--user-data-dir` |

## 已改配置（[cordis.patch.yml](C:\Users\liveu\.dsh\profiles\desktop\cordis.patch.yml#L225-L245) browser 条目）

- `channel: msedge` 保留
- 新增 `args: ["--user-data-dir=C:\Users\liveu\AppData\Local\Microsoft\Edge\UserDataDebug"]` → 和你 bat/edge mcp 同一套登录档（百度、贴吧 cookie 都在里面）
- 新增 `headless: false`（默认其实是 headless；可见窗口便于登录墙介入，patchright 隐身也建议可见）
- `authProfiles` 原样保留（patch 整段替换语义，必须写全）
- 注释里写明了 2026-10-17 这次改动的理由

## 风险与用法

- **profile 锁**：同一 `UserDataDebug` 同时只能被一个 Edge 进程占。用 dsh-browser 前关掉你 9222 的 MCP 实例；且那个 bat 第 41 行 `taskkill /F /IM msedge.exe` 会**杀掉全部 Edge 窗口**，不是只杀调试实例——跑它之前注意。
- 生效需**重启 DSH**（bundle 层配置）。重启后 `browser_call runtime.status` 看 `channel=msedge, headless=false` 确认；再开一个 tieba 页验证百度登录态还在。
- 后续：dsh-web-search-pro 的 tieba 平台后端要"browser 登录态"（`browserBindings.tieba` 绑 AuthProfile）——现在同源 profile 里若有百度 cookie，它读 tieba 的机会就大了；要不要我重启后直接试一次 `platform=tieba`？
