## 一、怎么用：三个层面

### 1）自动的部分（你什么都不用做）

装好之后，**每一轮问答结束就自动沉淀**：

```
turn/end → 提取 Q/A → 四层筛选 → 写 JSON + 落 MD → 建共现边 → 更新档案 → 排队下一轮「🧭 扩展思考」
```

具体表现为：

| 观察到什么 | 说明 |
|---|---|
| `~/.oblivion/data/ts-*.json` 增多 | 知识条目在沉淀 |
| `~/OblivionKB/10-Topics/*.md` 出现/增长 | 笔记落盘，**直接就是你的 Obsidian 库可用的格式**（四行头部合规） |
| 回答末尾偶尔出现 `## 🧭 扩展思考` | 认知陪伴触发（需累积 ≥4 个会话、档案置信度 ≥0.3、同一维度遗漏 ≥3 次） |
| 大部分问答**不**留下条目 | 正常——四层筛选在工作（防回灌、去重、低价值丢弃） |

**"扩展思考"不会一开始就有**：它有三道闸门（观察期 <4 会话不发、置信度 <0.3 不发、维度遗漏 <3 次不发）。这是设计里的防打扰机制，不是坏了。

## 二、设置页面：**现在看不到，而且这是刻意的**

我刚核实了：

| 检查项 | 结果 |
|---|---|
| `src/client/` 目录 | **不存在** |
| `package.json` 的 `dsh.client` 字段 | **没有**（纯 Host 侧） |
| `dshx.yml` 的 `kind` | `object` |

**为什么没有**：DSH 的设置页是**浏览器渲染的**，要占 `settings.section` 这个 UI slot 才有卡片。你有设置页的那两个插件（`oblivion-vimc`、`oblivion-brand`）都是 `kind: client`，声明了：

```json
"dsh": {
  "client": { "platform": "web", "inject": ["@deepseek-ai/dsh-client-ui-settings"] }
}
```

而 `@oblivion/core` 是纯服务端认知层——它连浏览器半边都没有，**没有可以渲染的东西**。官方对这两种形态是分开的，不能靠配置让纯 Host 插件长出设置页。

**但配置是可以改的**，只是改法不是点界面，而是改 profile 补丁：

```yaml
# %USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml
- insert:
    - id: '@oblivion/core'
      name: '@oblivion/core'
      config:              # ← 加这一段就能覆盖
        valueThreshold: 0.25
        perspectiveMinSessions: 6
        enablePerspective: false
```

20 个可调项：`dataRoot` / `mdRoot` / `semanticThreshold` / `valueThreshold` / `enablePerspective` / `enableFeedback` / `perspectiveMinSessions` / `perspectiveMinConfidence` / `perspectiveMinMisses` / `perspectiveDeepDiveTurns` / `graphInitialWeight` / `graphReinforceDelta` / `graphWeightCap` / `graphDecayBase` / `graphDecayPeriodDays` / `feedbackTuneThreshold` / `perspectiveOrder` / `maxPerspectivePerTurn` / `minAnswerLength` / `logPrefix`

⚠️ 两个实测坑：
- **patch 里的 `config` 是整段替换而不是深度合并**，所以要么全写、要么只写你想改的（`resolveConfig` 会补其余默认值）；
- **Host 侧改配置需要重启 App**（Host 复用 ESM 缓存），所以调参不要频繁改。

## 三、要不要给它加设置页？

我建议你按需求选，四条路都有明确代价：

| 方案 | 得到什么 | 代价 |
|---|---|---|
| **A. 保持现状**（推荐：先这样） | 5 个工具 + 自动沉淀，全都能用 | 调参要改 YAML 文件 |
| **B. 现状 + 配置注释**（我可以马上做） | 补丁文件里带注释说明每个参数含义，改起来不查文档 | 仍然没有界面 |
| **C. 加只读卡片** | 设置页出现「Oblivion 认知层」：显示条目数/边数/会话数/当前阈值 + 一个总开关 | `kind` 必须从 `object` 变 `client`；改 Host 侧代码**每次都要重启 App**（失去热挂）；工作量约等于半个 `oblivion-vimc` |
| **D. 加可编辑卡片** | 阈值、开关、画像编辑/重置都在界面里点 | C 的全部代价 + 需要客户端与 Host 之间的调用通道（要动 `package.json` 的 `dsh.compat.requires` 声明，`dshx check` 有对应闸门） |

**我的判断**：认知层现在最缺的不是界面，而是**先跑够一段时间**——阈值怎么调、陪伴频率合不合适，得有几天的真实数据才知道。所以建议**先 A**，等你积累到"我确实想调 X"的时候再决定是 B（够用）还是 C/D（值得）。

如果你现在就想改某个参数（比如觉得提醒太频繁、或者想让它多沉淀），**直接告诉我改哪个值**——我改 `cordis.patch.yml` 给你，比重做一个设置页快得多。

你要是倾向 C 或 D，我可以先出一份改动清单（要动哪些文件、`dshx check` 哪些闸门要过、激活方式怎么变），你确认后再动手——因为 C/D 会让这个插件从"可热挂"变成"改一次重启一次"，这个代价值得你亲自拍板。
