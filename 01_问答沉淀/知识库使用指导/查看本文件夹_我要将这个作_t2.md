## 一、先答你上一轮的两个问题（现在有了可运行的答案）

**1）"给个简便的词语/prompt"——不是给词，是给命令。**
单个词（比如"建索引"）每次都要靠 agent 猜含义，不可复现。我做成了**7 个固定动词**，谁执行结果都一样：

```
find  show  meta  stat  check  rebuild  stub
```

一句话用法，直接贴给任何 agent：

> 按 `_kb/10-调用协议.md` 检索知识库：先 `kb.py find` 拿 `文件:行号`，再 `kb.py show` 只读那几十行。不要整篇读。

**2）"要不要建几个 skill"——要，但只建一个，且不要放全局。**
放全局 skills 目录会改变你所有 agent 的行为，副作用大。我放在库内 `_kb/skill/knowledge-base-query/SKILL.md`（标准 frontmatter 格式），Codex / Claude Code / Trae 要用时复制或链接过去即可。真正的规则只有一个文件 `10-调用协议.md`，skill 只是它的入口壳。

**3）一个你没问但很关键的决定：我没有用 YAML frontmatter。**
你的库已经自成规范——四行 `>` 头部。硬塞 frontmatter 会打乱 Obsidian 属性面板和你的既有习惯。所以索引器**读你那四行**，并把缺头部的列入体检报告。附带好处已实测：**行序打乱、全角/半角冒号混用都能正确解析**（你这库两种冒号都在用）。
