构建成功。来总结根因和修复：

**问题根因：** esbuild 在解析 `String.raw` 模板字面量时，会把模板内容当作 JS 源码扫描。模板内的**单个反引号**会被解析为模板表达式边界，而不是文本字符。

- 行 163：`` `.dsh\web-login\transport-profile` `` 中的反引号触发 esbuild 尝试解析 `.dsh\web-login\transport-profile` 为 JS 表达式 → 遇到 `\w` 报 Syntax error
- 行 164：`` (`~/.dsh/`) `` 中的反引号触发 esbuild 把 `~` 解析为按位取反操作符 → 报 `Expected ";" but found "~"`

**已验证：** 双反引号转义 `\`\``（用于行 157/159/160 的代码标记）不会触发此问题，因为 esbuild 识别 `\`` 为转义序列而非模板终止符。

**修复内容：** 移除行 163 和 164 注释中的单反引号代码标记，同时将路径反斜杠改为正斜杠：

```diff
- # literal path `.dsh\web-login\transport-profile`.  This is safe because:
- #   - The path is user-scoped (`~/.dsh/`) so it only ever appears in our own
+ # literal path .dsh/web-login/transport-profile.  This is safe because:
+ #   - The path is user-scoped (~/.dsh/) so it only ever appears in our own
```
